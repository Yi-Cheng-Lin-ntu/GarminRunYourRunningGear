# Garmin Run Your Running Gear

Garmin Run 2026 的跑者風格與補水方式互動測驗 prototype。

這是使用 HTML、CSS 與 Vanilla JavaScript 的 static front end，可直接部署到 GitHub Pages。Quiz 本身不需要後端；永續補水投票使用 Supabase 儲存共用票數。

## 開發狀態

目前已完成第一版 functional MVP：

- Landing、六題測驗、結果、重新測驗流程
- 六題固定順序、全部必答、每題單選
- 每次測驗會隨機排列各題選項，但題目順序固定
- 返回上一題時保留該次測驗的選項排列，重新測驗才會重新排列
- Q6 支援五個選項，由資料動態產生
- 返回上一題後重新選擇會覆蓋舊答案
- 中英文 UI 與內容切換
- 三向度 rule-based classification 與集中式 tie-breaking
- 獨立的 sustainability boolean flag，不作為第四個分數向度
- 結果圖片預留固定路徑欄位，尚未放入正式圖片

目前題目與結果文案已依 MVP 規格配置；分類仍是活動互動用途，不代表正式心理測量結果。

## 永續補水投票（Supabase）

投票不收集姓名、email、Garmin ID 或 IP。每個瀏覽器在 `localStorage` 保存一個隨機 UUID；Supabase 只存該 UUID 的 SHA-256 雜湊 `voter_key_hash`，用來更新同一瀏覽器的既有票。票數仍由 Supabase 讀取，切換選項會更新原列，不會增加總票數。

### 1. 建立／遷移資料表與 RLS

在 Supabase Dashboard 的 SQL Editor 執行以下 SQL。腳本可用於新資料表，也會為現有資料表加入新欄位：

```sql
create extension if not exists pgcrypto with schema extensions;

create table if not exists public.votes (
	id bigint generated by default as identity primary key,
	option text not null check (option in ('try', 'watch', 'pioneer')),
	created_at timestamptz not null default now(),
	voter_key_hash text
);

alter table public.votes add column if not exists voter_key_hash text;
create unique index if not exists votes_voter_key_hash_unique
	on public.votes (voter_key_hash) where voter_key_hash is not null;

alter table public.votes enable row level security;

revoke all on public.votes from anon;
grant select (id, option, created_at) on public.votes to anon;
revoke all on sequence public.votes_id_seq from anon;

drop policy if exists "Anyone can read anonymous vote totals" on public.votes;
create policy "Anyone can read anonymous vote totals"
	on public.votes for select to anon using (true);

drop policy if exists "Anyone can add a valid anonymous vote" on public.votes;

create or replace function public.cast_vote(p_voter_id uuid, p_option text)
returns boolean
language plpgsql
security definer
set search_path = ''
as $$
declare
	hashed_voter_id text;
	previous_option text;
begin
	if p_voter_id is null or p_option is null or p_option not in ('try', 'watch', 'pioneer') then
		raise exception 'Invalid vote request';
	end if;

	hashed_voter_id := pg_catalog.encode(
		extensions.digest(p_voter_id::text, 'sha256'),
		'hex'
	);

	select option into previous_option
	from public.votes
	where voter_key_hash = hashed_voter_id;

	insert into public.votes (voter_key_hash, option)
	values (hashed_voter_id, p_option)
	on conflict (voter_key_hash) where voter_key_hash is not null
	do update set option = excluded.option, created_at = pg_catalog.now();

	return previous_option is not null;
end;
$$;

revoke all on function public.cast_vote(uuid, text) from public;
grant execute on function public.cast_vote(uuid, text) to anon;
```

RLS 允許匿名讀取票數所需欄位，但不允許直接 insert／update；只有 `cast_vote` RPC 能以雜湊 token 寫入或更新一列，且選項由資料庫再次驗證。舊資料列的 `voter_key_hash` 會是 `NULL`，無法和舊瀏覽器配對。

若這是測試專案，建議套用 migration 前先清除舊測試票，以免舊的匿名列繼續計入但不能被更新。若是已有正式資料的專案，舊票會保留為 legacy counts；新版本無法安全推測它們屬於哪個瀏覽器。

### 2. 開啟 Realtime

在 Supabase Dashboard 的 **Database → Replication**（或 Publications）將 `public.votes` 加入 `supabase_realtime` publication。瀏覽器訂閱 INSERT 與 UPDATE 事件；若連線中斷，頁面仍會每 30 秒重新讀取票數。

### 3. 設定前端金鑰

在 `js/supabase.js` 填入 Supabase **Project URL** 與公開的 **anon / publishable key**：

```js
const SUPABASE_URL = "https://your-project.supabase.co";
const SUPABASE_ANON_KEY = "your-public-anon-or-publishable-key";
```

這是靜態網站，瀏覽器中的公開金鑰人人可見；安全性依賴上方的 RLS。**絕不可放入 `service_role` key。**

### Demo 與測試

- `js/voteData.js` 的 `DEMO_MODE` 預設為 `true`，方便尚未設定 Supabase 時點選測試；頁面會標示 development/demo，使用目前程式中的 seed 數字，投票只在目前頁面記憶體中模擬，不會寫入 Supabase。同一瀏覽器重新選擇時，demo 也會減去舊選項並加到新選項。設定 Supabase 後、正式部署前務必改成 `false`。
- 測試不同總票數時，暫時將 `DEMO_SEED_COUNTS` 改成下列任一組，再重新載入頁面：10 票 `{ try: 4, watch: 3, pioneer: 3 }`、100 票 `{ try: 36, watch: 30, pioneer: 34 }`、1,000 票 `{ try: 360, watch: 300, pioneer: 340 }`、10,000 票 `{ try: 3600, watch: 3000, pioneer: 3400 }`。總票數會影響堆高，比例會影響顏色；視覺球最多 100 顆，因此 1,000 與 10,000 票都不會增加 DOM 數量。
- 本機以 `python3 -m http.server 8000` 啟動後開啟 <http://localhost:8000>。填好 URL / key 與建表，並將 `DEMO_MODE` 設為 `false`，即可測試真實共用票數；若維持 `DEMO_MODE = false` 但尚未設定 Supabase，投票頁會顯示無法更新訊息，原測驗結果仍可正常使用。
- 用兩個分頁同時開啟投票頁，在其中一頁切換選項；另一頁應不用重新整理就更新票數。相同瀏覽器 token 重新選擇會更新既有列，只有第一次投票會增加總數。連線狀態顯示「即時更新中」代表 Realtime 已訂閱；暫停時會由 30 秒輪詢接手。
- `localStorage.removeItem("garmin-run-hydration-vote")` 會建立新的匿名瀏覽器 token，不是清除或重設舊票。真實模式下，只有在刻意模擬另一位新跑者時才清除此值；要清測試票請使用下一項 SQL。
- 清除 Supabase 測試票數（會刪除該資料表中的所有票）：在 SQL Editor 執行 `truncate table public.votes restart identity;`。正式活動資料也會一併清除，執行前請確認專案環境。

GitHub Pages 可直接部署此 static site，不需要 Node.js backend。Supabase SDK 由 `supabase.js` 以瀏覽器 ESM CDN 載入。

UI 不會判斷某個答案屬於哪一種跑者類型。分類器在完成最後一題時，依照目前 `answers` 重新計算所有 trait，因此返回修改答案不會產生 double scoring。

## 修改題目或分類

一般分類選項使用三向度的 `traits` 陣列：

```js
{
	id: "q1_a",
	text: {
		zh: "選項文字",
		en: "Option text"
	},
	traits: ["experience"]
}
```

Meme 或 sustainability 選項不應增加三向度分數：

```js
traits: [],
isMeme: true
```

永續選項使用獨立 flag：

```js
traits: [],
sustainability: true
```

Q6 的所有選項都不影響 runnerType；只有 Q6 永續選項可以觸發 sustainability flag。

目前 tie-break 流程是：

1. 只計算 Q1-Q5 的 `experience`、`lifestyle`、`performance`
2. 最高分唯一時直接使用該 runner type
3. 平手時依 `classificationRules.js` 的順序：`experience` > `lifestyle` > `performance`
4. Q2、Q4、Q6 的 sustainability option 只設定 flag，不進入 scores

這些是 placeholder rules，尚未代表正式分類設計。
