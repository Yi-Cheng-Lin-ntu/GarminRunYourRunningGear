# Garmin Run Your Running Gear

Garmin Run 2026 的跑者風格與補水方式互動測驗 prototype。

這是一個不需要 backend 的 static website，使用 HTML、CSS 與 Vanilla JavaScript，可直接部署到 GitHub Pages。

## 開發狀態

目前已完成第一版 functional MVP：

- Landing、六題測驗、結果、重新測驗流程
- 六題固定順序、全部必答、每題單選
- 每次測驗會隨機排列各題選項，但題目順序固定
- 返回上一題時保留該次測驗的選項排列，重新測驗才會重新排列
- Q6 支援五個選項，由資料動態產生
- 返回上一題後重新選擇會覆蓋舊答案
- 中英文 UI 與內容切換
- 三向度 rule-based classification 與集中式 tie-breaking
- 獨立的 sustainability boolean flag，不作為第四個分數向度
- 結果圖片預留固定路徑欄位，尚未放入正式圖片

目前題目與結果文案已依 MVP 規格配置；分類仍是活動互動用途，不代表正式心理測量結果。

### 資料與責任邊界

- `quizData.js`：Q1-Q6、選項、雙語文字、`traits`、`isMeme` 與 `sustainability`
- `classificationRules.js`：三向度 runner types 與 tie-break order
- `classificationEngine.js`：計算三向度分數、sustainability flag 與最終 result object
- `resultData.js`：三種 runner type、永續組合文案、補水建議、圖片路徑與 CTA 內容
- `app.js`：測驗狀態、DOM rendering、答案儲存與頁面導覽
- `hydrationVote.js`：永續補水投票頁、票數呈現、容器粒子、Realtime 與輪詢 fallback
- `voteData.js`：共用票數讀取、投票寫入與 demo seed 設定
- `supabase.js`：Supabase client 初始化與公開 URL / anon key 設定
- `style.css`：mobile-first layout 與視覺樣式

## 永續補水投票（Supabase）

投票只儲存 `option` 與資料庫自動產生的 `id`、`created_at`，不收集個人資料。票數由 Supabase 讀取；`localStorage` 只用來避免同一瀏覽器重複投票，不作為票數來源。

### 1. 建立資料表與 RLS

在 Supabase Dashboard 的 SQL Editor 執行以下 SQL：

```sql
create table public.votes (
	id bigint generated by default as identity primary key,
	option text not null check (option in ('try', 'watch', 'pioneer')),
	created_at timestamptz not null default now()
);

alter table public.votes enable row level security;
grant select, insert on public.votes to anon;
grant usage, select on sequence public.votes_id_seq to anon;

create policy "Anyone can read anonymous vote totals"
	on public.votes for select to anon using (true);

create policy "Anyone can add a valid anonymous vote"
	on public.votes for insert to anon
	with check (option in ('try', 'watch', 'pioneer'));
```

公開讀取僅包含選項與時間戳，不包含個人識別資料。RLS 限制匿名寫入只能使用三個允許的選項。

### 2. 開啟 Realtime

在 Supabase Dashboard 的 **Database → Replication**（或 Publications）將 `public.votes` 加入 `supabase_realtime` publication。瀏覽器訂閱 INSERT 事件；若連線中斷，頁面仍會每 30 秒重新讀取票數。

### 3. 設定前端金鑰

在 `js/supabase.js` 填入 Supabase **Project URL** 與公開的 **anon / publishable key**：

```js
const SUPABASE_URL = "https://your-project.supabase.co";
const SUPABASE_ANON_KEY = "your-public-anon-or-publishable-key";
```

這是靜態網站，瀏覽器中的公開金鑰人人可見；安全性依賴上方的 RLS。**絕不可放入 `service_role` key。**

### Demo 與測試

- `js/voteData.js` 的 `DEMO_MODE` 預設為 `true`，方便尚未設定 Supabase 時點選測試；頁面會標示 development/demo，使用 46、39、43 seed 數字，投票只在目前頁面記憶體中模擬，不會寫入 Supabase。設定 Supabase 後、正式部署前務必改成 `false`。
- 測試不同總票數時，暫時將 `DEMO_SEED_COUNTS` 改成下列任一組，再重新載入頁面：10 票 `{ try: 4, watch: 3, pioneer: 3 }`、100 票 `{ try: 36, watch: 30, pioneer: 34 }`、1,000 票 `{ try: 360, watch: 300, pioneer: 340 }`、10,000 票 `{ try: 3600, watch: 3000, pioneer: 3400 }`。總票數會影響堆高，比例會影響顏色；視覺球最多 100 顆，因此 1,000 與 10,000 票都不會增加 DOM 數量。
- 本機以 `python3 -m http.server 8000` 啟動後開啟 <http://localhost:8000>。填好 URL / key 與建表，並將 `DEMO_MODE` 設為 `false`，即可測試真實共用票數；若維持 `DEMO_MODE = false` 但尚未設定 Supabase，投票頁會顯示無法更新訊息，原測驗結果仍可正常使用。
- 用兩個分頁同時開啟投票頁，在其中一頁投票；另一頁應不用重新整理就更新數字並顯示新粒子。連線狀態顯示「即時更新中」代表 Realtime 已訂閱；暫停時會顯示定期更新狀態，並由 30 秒輪詢接手。
- 清除本機投票鎖定：在該瀏覽器的開發者工具執行 `localStorage.removeItem("garmin-run-hydration-vote")`，再重新載入。此操作不會刪除共用票數。
- 清除 Supabase 測試票數（會刪除該資料表中的所有票）：在 SQL Editor 執行 `truncate table public.votes restart identity;`。正式活動資料也會一併清除，執行前請確認專案環境。

GitHub Pages 可直接部署此 static site，不需要 Node.js backend。Supabase SDK 由 `supabase.js` 以瀏覽器 ESM CDN 載入。

UI 不會判斷某個答案屬於哪一種跑者類型。分類器在完成最後一題時，依照目前 `answers` 重新計算所有 trait，因此返回修改答案不會產生 double scoring。

## 修改題目或分類

一般分類選項使用三向度的 `traits` 陣列：

```js
{
	id: "q1_a",
	text: {
		zh: "選項文字",
		en: "Option text"
	},
	traits: ["experience"]
}
```

Meme 或 sustainability 選項不應增加三向度分數：

```js
traits: [],
isMeme: true
```

永續選項使用獨立 flag：

```js
traits: [],
sustainability: true
```

Q6 的所有選項都不影響 runnerType；只有 Q6 永續選項可以觸發 sustainability flag。

目前 tie-break 流程是：

1. 只計算 Q1-Q5 的 `experience`、`lifestyle`、`performance`
2. 最高分唯一時直接使用該 runner type
3. 平手時依 `classificationRules.js` 的順序：`experience` > `lifestyle` > `performance`
4. Q2、Q4、Q6 的 sustainability option 只設定 flag，不進入 scores

這些是 placeholder rules，尚未代表正式分類設計。
